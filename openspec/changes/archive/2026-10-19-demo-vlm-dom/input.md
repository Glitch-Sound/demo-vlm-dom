# 入力仕様

## 1. 目的
`VLM(Vision Language Model / 視覚言語モデル)` と `DOM(Decision Only Model / 意思決定特化モデル)` を活用したデモを作成したい。<br />


## 2. 前提

### 2.1. 環境
- `Mac` または `Ubuntu` で動作する
- `Python 3.13` を利用する
- `VLM` や `DOM` は別途起動している `Ollama` にダウンロード済みとする
  モデルは以下を利用する
    - `VLM` : qwen2.5vl:7b
    - `DOM` : tev1

### 2.2. 画像ファイル
- 入力は画像ファイルとし、ドラレコのような走行画像とする
- 大きな入力画像は、設定した推論用画像の最大幅・最大高さに収まるよう、縦横比を保って縮小してから `VLM` に渡す。<br />
  元画像が設定範囲内に収まる場合は拡大しない
- 描画と出力には元画像を使い、出力する画像ファイルの幅・高さと形式は入力と同じとする
- 同名の出力ファイルがすでにある場合は、今回の処理に成功した画像で上書きする

### 2.3. 失敗時の扱い
- 画像ごとの処理に失敗した場合は、その画像を失敗としてコンソールにファイル名と原因をログ出力し、残りの画像の処理を続ける。<br />
  失敗した画像の出力ファイルは新たに作成・上書きしない
- `Ollama` に接続できない、モデルの事前ロードまたは実際の推論が失敗・タイムアウトした場合は、対象モデルと失敗した段階を示す。<br />
  事前ロードに失敗したモデルは、後続の画像で必要になった際に再試行する
- 入力画像が破損している、または入力画像と同じ形式で出力できない場合は、その原因を示す
- `VLM` の応答がJSONとして解析できない、指定した構造に合わない、または車両IDが重複する場合は、その原因を示す
- `DOM` の応答に対象車両の `choice` がない、または指定外の値が返った場合は、その原因を示す。<br />
  正常な選択肢である「判定不能」はこの失敗に含めない
- 全画像の処理後に、成功件数と失敗件数、失敗したファイル名をコマンドの結果に示す

### 2.4. 試験
- デモのため、詳細な検出精度評価は行わない
- 入出力、縮小と座標換算、元画像サイズの維持、失敗時の扱いは少数の自動テストで確認する
- 実静止画を用いた最低限の動作確認を行う
- 自動テストは `Mac` または `Ubuntu` どちらかで通れば問題ないものとする
- 初回ロードを含む実静止画での動作確認では、事前ロードと実際の推論を別々に確認する

### 2.5. モデルの事前ロード
- `VLM` は最初の画像解析の直前に、モデル名と空の `prompt` を指定した `/api/generate` 要求を送り、ロード完了応答を確認する
- `DOM(tev1)` は `/api/generate` に対応しないため、最初の車両判定の直前に、固定の短い `state` と `choice` 質問を `/v1/systemone` に送って応答を確認する。<br />
  質問には `ready` と `other` の選択肢を設け、いずれかの `choice` が返れば応答成功とする。選択結果は車両の優先度に使用しない
- 両モデルの事前ロードはそれぞれ初回使用直前に行う。<br />
  両モデルを起動時にまとめてロードすることは前提としない
- 事前ロードのタイムアウトは通常の推論タイムアウトと別に設定できるようにし、モデルの初回ロード時間を考慮する
- 事前ロード後にモデルがメモリから解放される可能性を考慮し、保持時間を設定できるようにする。<br />
  事前ロードの応答はモデルが応答可能なことの確認であり、実際の画像解析や車両判定が正しいこと、以後の推論でタイムアウトしないことの確認には使わない

### 2.6. モデルの入出力と座標
- `VLM(qwen2.5vl)` には、必要に応じて縮小した推論用画像と、画像内で識別できる自車以外の車両の抽出指示を渡す
- `VLM` の出力はJSON Schemaで形式を固定したJSONテキストとし、場面の説明と車両の配列を含める
- 場面には自車が走る車線、各車両には同じ画像内で一意なID、矩形、その車両の車線を含む自車の前方進路との位置関係、その判断に使った画像上の根拠を含める。<br />
  自車線は見える同方向の車線を左・中央・右・単一で区別し、車線数や境界が曖昧で一意に区別できない場合は不明とする
- 車両が見つからない場合は、車両の配列を空にする。<br />
  画像から読み取れない位置関係は不明とし、推測で埋めない
- `VLM` は車両の優先度を決めない。<br />
  優先度の判定は `DOM` に任せる
- JSONテキストは `json.loads()` で読み取り、型、要素数、座標の範囲を検証する
- 正規表現で不定形の文章から座標を抽出しない
- `VLM` が返す矩形は、送信した推論用画像の絶対ピクセル座標で `[xmin, ymin, xmax, ymax]` とし、左上を原点、右方向を `x`、下方向を `y` とする。<br />
  `xmin < xmax`、`ymin < ymax` で、すべての座標が推論用画像内に収まることを求める
- 不正な矩形は抽出後に破棄し、有効な矩形だけを元画像の絶対ピクセル座標へ換算してから後続の判定と描画に使う。<br />
  矩形の右端・下端は含まず、換算時は左上を切り下げ、右下を切り上げる
- `DOM` には画像を直接渡さず、`VLM` が出力した自車線、場面の説明と車両ごとの車線を含む位置関係・根拠を判定材料として渡す。<br />
  矩形とIDを対応付け、各車両の判定が混ざらないようにする
- `DOM` はOllamaの `/v1/systemone` を用い、車両ごとの判定を `choice` 形式で受け取る。<br />
  選択肢は優先度「高」「中」「低」と、判断材料が不足する場合の「判定不能」とする
- `VLM` が位置関係を不明とした車両は「判定不能」とし、`DOM` に不足した根拠を推測させない
- 選択結果は `answers` 内の各質問の `choice` から読む
- モデルへの指示、JSONのキー、`choice` のキーと判定基準は英語とする。<br />
  利用者への表示と設定項目の説明は日本語とする
- 静止画像から確認できない車両の速度、進行方向の変化、車線変更の意思、将来の衝突可能性、正確な車間距離は推測しない

### 2.7. 判定と描画
- 優先度は衝突リスクの予測値ではなく、静止画像で確認できる自車の前方進路との位置関係に基づく注視の順序とする
- 「高」は、画像上ですぐ前方に見え、自車の走行車線上または自車の前方進路と重なる位置にある車両とする
- 「中」は、画像上で前方近くに見え、隣接車線や交差点付近など、自車の前方進路には重ならない車両とする
- 「低」は「高」「中」以外とする。<br />
  画像上で少し離れて見える車両や反対車線の車両はこれに当たる。実距離や速度は推測せず、画像内の見かけの大きさと配置を使う
- 前方に見えるという理由だけで「高」にしない。<br />
  自車線と対象車両の車線が異なる場合は、進路と重なる画像上の根拠が明示されない限り「高」にしない
- 遠方に見えることが明らかな車両は、車線が読めなくても「低」とする
- 「高」と「中」の両方に当てはまる場合は「高」を優先する。<br />
  画像上の根拠が不足して位置関係を判断できない場合は「判定不能」とし、「低」に含めない
- 「高」の車両は赤枠、「中」の車両は黄枠、「低」の車両は青枠で、元画像上の対応する位置に描画する
- 「判定不能」の車両と不正な矩形の車両は描画せず、件数と理由をログとコマンドの結果に示す
- 車両が見つからない場合は処理成功とし、矩形を描画せずに元画像と同じ幅・高さ・形式で出力し、その旨をコマンドの結果に示す

## 3. 構成
- デモとなるため、シンプルなファイル構成とすること
- 設定ファイル、入出力の画像ファイルの格納先は以下とする。
- `src`配下もシンプルなファイル構成とすること

```text
demo-vlm-dom
├── config/
│   └── setting.ini               # 設定ファイル
│
├── data/
│   ├── src/                      # 入力画像ファイルの格納先
│   └── dest/                     # 出力画像ファイルの格納先
│
└── src/                          # ソース格納先
```


## 4. 設定ファイル

### 4.1. setting.ini
- `ollama` の接続先、通常の推論タイムアウト、事前ロードのタイムアウト、モデルの保持時間など、必要な設定を定義可能とすること
- 推論用画像の最大幅 `inference_max_width` と最大高さ `inference_max_height` を正の整数で指定できるようにする。<br />
  既定値はそれぞれ `1280` px と `720` px とし、設定値は出力画像のサイズを変更しない
- 各検出枠の太さ、カラーコードも定義してほしい
- カラーコードのデフォルト値はRGB形式で以下とする

| 対象 | 色 | デフォルト値 |
| --- | --- | --- |
| 注意する優先度が高い車両 | 赤色 | `#FF0000` |
| 注意する優先度が中程度の車両 | 黄色 | `#FFFF00` |
| 注意する優先度が低い車両 | 青色 | `#0000FF` |

## 5. コマンド
各コマンドは結果、処理時間、適切なログを見やすく出力すること。

### 5.1. デモ実行
```bash
uv run --locked demo
```

`data/src` 配下の画像ファイルを読み込み、`VLM`にて取得、`DOM`にて判定した情報を重畳し、`data/dest` 配下へ出力する。<br />
以下情報を追加すること。<br />
以下に記載する描画色は既定色とし、`setting.ini` で指定した色を優先する。

#### 5.1.1. 注意する優先度が高い車両
- `VLM` のグラウンディング機能で取得した座標を元に、画像内の車両を **赤色** の矩形枠で囲むこと

#### 5.1.2. 注意する優先度が中程度の車両
- `VLM` のグラウンディング機能で取得した座標を元に、画像内の車両を **黄色** の矩形枠で囲むこと

#### 5.1.3. 注意する優先度が低い車両
- `VLM` のグラウンディング機能で取得した座標を元に、画像内の車両を **青色** の矩形枠で囲むこと
