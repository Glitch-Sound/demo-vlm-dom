## Purpose

デモ実行者が前方の走行風景を写した静止画像をまとめて渡し、画像内の他車について自車の前方進路との位置関係に基づく注視優先度を色付きの枠で確認できるようにする。
結果と失敗した画像を区別して受け取り、画像の見直しや再実行を判断できる。

| 用語・結果 | 非開発者向けの意味 | 利用者・運用者による扱い |
| --- | --- | --- |
| 注視優先度 | 静止画像で見える自車の前方進路と他車との位置関係による注視の順序。衝突可能性の予測ではない | 高・中・低の色付き枠を比較する |
| 判定不能 | 車線や前方進路などの画像上の根拠が足りず、位置関係を決められない状態 | 枠を付けず、件数と理由を確認する |
| 画像ごとの失敗 | 画像の読取、モデルとのやり取り、出力などが完了しなかった状態 | ファイル名と原因を確認し、必要なら再実行する |

## ADDED Requirements

### Requirement: REQ-001 複数画像のデモ実行

システムは、デモ実行者が `demo` コマンドを起動した時に、入力場所にある画像を画像ごとに処理しなければならない (MUST)。

#### Scenario: REQ-001-S01 複数画像を順に扱う

- **GIVEN** 入力場所に複数の走行静止画像がある
- **WHEN** デモ実行者が `demo` コマンドを起動する
- **THEN** 各画像について成功または失敗の結果が得られ、一画像の失敗によって後続の画像が省略されない

### Requirement: REQ-002 画像からの他車と位置関係の取得

システムは、走行静止画像を解析する時に、設定した最大幅・最大高さに収まる推論用画像を VLM に渡し、画像で識別できる自車以外の車両の矩形と前方進路との位置関係を得なければならない (MUST)。

推論用画像は縦横比を維持し、元画像が設定範囲内に収まる場合は拡大しない。
VLM の矩形は推論用画像の絶対ピクセル座標で検証し、有効な矩形を元画像の絶対ピクセル座標へ換算して後続の判定と描画に渡す。
VLM は自車線を示し、各車両の車線を位置関係とその画像上の根拠に記述する。位置関係とその根拠が画像から読み取れないときは不明とする。
自車線は見える同方向の左・中央・右・単一で表し、車線数や境界が曖昧で一意に区別できない場合は不明とする。
車両ごとの ID は同じ画像内で一意とし、矩形は `[xmin, ymin, xmax, ymax]`、`xmin < xmax`、`ymin < ymax`、全座標が対応する画像内という条件を満たす。
速度、進行方向の変化、車線変更の意思、将来の衝突可能性、正確な車間距離は推測しない。

#### Scenario: REQ-002-S01 車両の矩形と根拠を得る

- **GIVEN** 車線と他車が見える走行静止画像がある
- **WHEN** デモ実行者がその画像を処理する
- **THEN** 他車ごとの一意な ID、画像内の有効な矩形、場面の説明、自車線、対象車両の車線を含む位置関係と画像上の根拠に対応する結果が後続の判定に渡される

#### Scenario: REQ-002-S02 不正な矩形を除く

- **GIVEN** 車両の抽出結果に逆転座標または画像外座標の矩形が含まれる
- **WHEN** デモ実行者がその画像を処理する
- **THEN** 不正な矩形の車両には枠が付かず、除外件数と理由が表示される

#### Scenario: REQ-002-S03 解析結果の形式が壊れている

- **GIVEN** 画像解析の結果が指定した JSON 構造を満たさない、または車両 ID が重複する
- **WHEN** デモ実行者がその画像を処理する
- **THEN** その画像は失敗としてファイル名と原因が表示され、出力は更新されない

#### Scenario: REQ-002-S04 大きな画像を縮小して座標を戻す

- **GIVEN** 元画像が推論用の最大幅または最大高さを超え、車両が見える
- **WHEN** デモ実行者がその画像を処理する
- **THEN** 縦横比を維持した範囲内の画像で推論し、有効な矩形は元画像上の対応する位置へ換算される

### Requirement: REQ-003 車両ごとの注視優先度

システムは、他車の位置関係が得られた時に、車両ごとに「高」「中」「低」または「判定不能」の結果を与えなければならない (MUST)。

「高」は画像上ですぐ前方に見え、自車の走行車線上または前方進路と重なる位置、「中」は画像上で前方近くに見え、進路に重ならない隣接車線や交差点付近、「低」は画像上で少し離れて見える車両や反対車線の車両など、高・中のどちらにも当てはまらない場合とする。
見かけの近さは画像内の車両の大きさと配置で判断し、実距離を推測しない。離れた車両は車線が読み取れなくても、離れて見える根拠があれば低とする。
高と中の両方に当てはまる場合は高とし、位置関係が不明なら低へ繰り入れず判定不能とする。
前方に見えることだけを高の根拠にしてはならない。自車線と対象車両の車線が異なる場合は、前方進路と重なる画像上の根拠が明示されない限り高にしてはならない。

#### Scenario: REQ-003-S01 三段階を区別する

- **GIVEN** 前方進路上、進路の近く、どちらにも当てはまらない位置にそれぞれ他車が見える
- **WHEN** デモ実行者がその画像を処理する
- **THEN** 対応する車両に高・中・低の区分が割り当てられ、高と中の条件が重なる車両は高となる

#### Scenario: REQ-003-S02 根拠不足を区別する

- **GIVEN** 他車は見えるが自車の前方進路との関係が画像から判断できない
- **WHEN** デモ実行者がその画像を処理する
- **THEN** その車両は判定不能となり、高・中・低の枠は付かず、理由が表示される

#### Scenario: REQ-003-S03 判定応答が壊れている

- **GIVEN** 判定結果に車両の選択肢がない、または指定外の値がある
- **WHEN** デモ実行者がその画像を処理する
- **THEN** その画像は失敗としてファイル名と原因が表示され、出力は更新されない

#### Scenario: REQ-003-S04 隣接車線の前方車両を高にしない

- **GIVEN** 自車線が中央で、対象車両が左の隣接車線の前方に見え、前方進路と重なる根拠がない
- **WHEN** デモ実行者がその車両を判定する
- **THEN** 前方に見えることだけを理由に高とせず、中とする

#### Scenario: REQ-003-S05 離れた車両を低にする

- **GIVEN** 画像上で小さく離れて見える車両と、すぐ前方の車両が同じ画像にある
- **WHEN** デモ実行者が車両ごとの優先度を確認する
- **THEN** 離れた車両は車線にかかわらず低、すぐ前方で同じ車線の車両は高となる

### Requirement: REQ-004 同形式の注釈画像

システムは、画像ごとの解析と判定に成功した時に、判定された車両に元画像の座標で枠を付け、入力画像と同じ寸法・形式で出力しなければならない (MUST)。

高は赤、中は黄、低は青を既定色とし、設定された色と枠の太さがあればその値を使う。

#### Scenario: REQ-004-S01 三色の枠を描画する

- **GIVEN** 高・中・低と判定された車両を含む画像があり、枠の色と太さが設定されている
- **WHEN** デモ実行者がその画像を処理する
- **THEN** 各車両に設定値による矩形枠が付いた同形式の画像を受け取る

#### Scenario: REQ-004-S02 車両を検出しない

- **GIVEN** 画像から他車が検出されない
- **WHEN** デモ実行者がその画像を処理する
- **THEN** 矩形を付けない元画像と同じ寸法・形式の出力画像を受け取り、その画像は成功として報告される

#### Scenario: REQ-004-S03 縮小推論後も元画像の寸法で出力する

- **GIVEN** 元画像より小さい推論用画像で車両を解析した
- **WHEN** デモ実行者がその画像を処理する
- **THEN** 元画像の対応位置に枠が付き、出力の幅・高さと形式は元画像と一致する

### Requirement: REQ-005 画像ごとの失敗と継続

システムは、ある画像の処理に失敗した時に、その画像の出力を更新せず、ファイル名と原因をコンソールに示して後続の画像を処理しなければならない (MUST)。

対象には入力破損、接続・ロード・推論の失敗またはタイムアウト、同形式での出力失敗を含む。

#### Scenario: REQ-005-S01 失敗後も後続画像を処理する

- **GIVEN** 一番目の画像が破損し、二番目の画像は有効である
- **WHEN** デモ実行者が二枚をまとめて処理する
- **THEN** 一番目のファイル名と原因が表示され、二番目の出力が得られる

#### Scenario: REQ-005-S02 失敗した画像の旧出力を保持する

- **GIVEN** ある画像に対応する既存出力があり、その画像のモデル呼び出しまたは同形式での出力が失敗する
- **WHEN** デモ実行者がその画像を再処理する
- **THEN** 既存出力は更新されず、失敗したファイル名と段階・原因が表示される

### Requirement: REQ-006 成功時の再実行と上書き

システムは、画像の処理に成功し、同名の出力が既にある場合、その出力を今回の結果で上書きしなければならない (MUST)。

#### Scenario: REQ-006-S01 再実行した成功画像を更新する

- **GIVEN** 入力画像と同名の旧出力がある
- **WHEN** デモ実行者が画像を正常に再処理する
- **THEN** 同名の出力が今回の判定結果を示す画像に更新される

### Requirement: REQ-007 初回ロードと推論の区別

システムは、VLM の初回画像解析前に空の `/api/generate` 要求へのロード完了応答を確認し、DOM の初回車両判定前に固定の短い `state` と `choice` 質問を `/v1/systemone` に送って有効な応答を確認しなければならない (MUST)。

事前ロードは VLM の初回画像解析直前と DOM の初回車両判定直前にそれぞれ実施する。
DOM の事前ロードでは `ready` または `other` の選択結果を応答確認だけに使い、車両の優先度に使用しない。
事前ロードの成功は実推論の成功を意味しない。

#### Scenario: REQ-007-S01 事前ロード後に推論する

- **GIVEN** 指定モデルが未ロードであり、VLM の空要求と DOM の固定質問による事前ロードが成功する
- **WHEN** デモ実行者が対象モデルを必要とする画像を処理する
- **THEN** 対象モデルのロード完了後に実際の解析または判定が行われ、両段階の結果が区別して確認できる

#### Scenario: REQ-007-S02 ロード失敗後に再試行する

- **GIVEN** 一番目の画像で必要なモデルの事前ロードが失敗し、二番目の画像では応答する
- **WHEN** デモ実行者が二枚をまとめて処理する
- **THEN** 一番目は失敗として表示され、二番目で該当モデルの事前ロードが再試行され、後続処理が行われる

### Requirement: REQ-008 設定による動作変更

システムは、デモ実行者が接続先、通常推論と事前ロードのタイムアウト、モデル保持時間、推論用画像の最大幅・最大高さ、三色と枠の太さを設定した場合、その値を使用しなければならない (MUST)。

#### Scenario: REQ-008-S01 設定値を反映する

- **GIVEN** 接続先、二種類のタイムアウト、保持時間、推論用画像の最大幅・最大高さ、三色と枠の太さが設定されている
- **WHEN** デモ実行者が `demo` コマンドを起動する
- **THEN** 指定先のモデルと設定した時間・画像寸法条件で処理され、出力画像には設定した色と太さが反映される

### Requirement: REQ-009 実行結果の集計

システムは、全画像の処理が終わった時に、成功件数、失敗件数、失敗したファイル名と処理時間をコマンドの結果に示さなければならない (MUST)。

#### Scenario: REQ-009-S01 成功と失敗を区別して報告する

- **GIVEN** 成功した画像と失敗した画像がある
- **WHEN** デモ実行者が `demo` コマンドの終了結果を確認する
- **THEN** 成功件数、失敗件数、失敗したファイル名、処理時間が分かる

### Requirement: NREQ-001 対象 OS での実行

システムは、Python 3.13 と必要なモデルを用意した Mac または Ubuntu でデモ実行者が `demo` コマンドを実行した場合、同じ入出力契約の結果を提供しなければならない (MUST)。

#### Scenario: NREQ-001-S01 対象環境で静止画像を処理する

- **GIVEN** Mac または Ubuntu に Python 3.13、Ollama、指定モデル、実静止画が用意されている
- **WHEN** デモ実行者が `demo` コマンドを実行する
- **THEN** 対象環境で同形式の出力画像と実行結果を確認できる

## 試験方針

| 要件区分 | 試験層 | 試験パターン | 自動化方針・利用者が確認する結果 |
| --- | --- | --- | --- |
| 機能要件 | unit / integration / CLI | 三段階・判定不能、縮小と座標換算、元寸法出力、座標境界、無検出、形式不正、画像別継続、再実行、ロード失敗 | 全 Scenario に pytest の自動テストを設け、出力画像、コンソール表示、既存出力の保持を確認する。実モデルによる結果は別途実静止画で確認する |
| 非機能要件 | integration / 対象 OS の実行確認 | Mac または Ubuntu での CLI 起動と画像の読書き | 自動テストを対象 OS の少なくとも一方で実行し、実 Ollama・実静止画の受け入れ結果と未確認の OS を別に記録する |
